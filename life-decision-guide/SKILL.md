# Life Decision Guide

把“人生经验”改成“证据约束下的决策”。

核心原则只有三条：

1. **先查证据，再做判断。** 不凭记忆补数字、法条、论文、政策或结论。
2. **不把不可比的收益硬加成一个总分。** 寿命、时间、金钱、人身自由分别呈现；必要时再让用户说明偏好。
3. **优先避免不可逆的大错，再追求高性价比的小收益。** 低成本、可逆、证据较强的动作优先；高风险、不可逆、证据弱的动作先验证或缩小下注。

## 0. 先判断是不是本 Skill 的任务

触发本 Skill 的典型问题：

- “这个东西值不值得买？”
- “我要不要辞职 / 读研 / 转行 / 结婚 / 生孩子 / 买房 / 出国？”
- “这件事应该先做什么？”
- “帮我比较两个生活方案，哪个更适合我？”
- “这么做的风险是什么，怎么把损失封顶？”
- “书里对这个问题怎么说？”

不要因为出现“选择”“建议”“值不值”就误触发。纯写作、纯陪伴、知识解释、创意发散、专业诊断或政治选择不属于本 Skill。

## 1. 先做安全闸门

在任何性价比分析前，先读 `references/safety-boundaries.md` 并判断是否存在：

- 立即生命危险或正在发生的急症、火灾、溺水、触电、中毒等。
- 自伤、自杀或他伤风险。
- 已进入传唤、拘留、起诉、诉讼、仲裁等具体法律程序。
- 需要个体诊断、处方、停药/换药的医疗问题。
- 具体证券、杠杆、借贷投资等高风险金融操作。
- 其他可能造成重大、不可逆损失的行动。

命中安全闸门时，先给安全动作和专业渠道，再做一般信息梳理。不要让“性价比”压过安全。

## 2. 确定决策问题

把用户问题改写为一个明确决策：

- **对象**：到底在决定什么。
- **选项**：至少列出当前可行的 A / B；必要时增加“暂不决定 / 小规模试验”。
- **时间窗**：这是今天要做、未来一年做，还是长期策略。
- **关键约束**：预算、时间、健康、安全、家庭责任、所在地、不可接受结果。
- **成功标准**：用户真正想换回什么。

如果缺失信息会改变结论，最多只追问 1–3 个最高影响问题。若用户希望直接给方案，就采用保守假设并明确写出假设，不因缺信息停住整个回答。

## 3. 检索《高性价比人生指南》

优先使用本 Skill 自带的固定版本：

- 正文：`assets/upstream/book/`
- 长文：`assets/upstream/docs/`
- 上游目录与章节映射：`assets/upstream/README.md`
- 上游排序公式：`assets/upstream/index.html`
- 来源版本：`assets/upstream/SOURCE.json`
- 许可：`assets/upstream/LICENSE`

先用确定性脚本检索：

```bash
python3 scripts/query_guide.py --json 关键词1 关键词2
```

需要缩小章节时：

```bash
python3 scripts/query_guide.py --section 5 --json 关键词
```

需要完整条目时：

```bash
python3 scripts/query_guide.py --full --json 关键词
```

需要看全部章节时：

```bash
python3 scripts/query_guide.py --list-sections
```

检索要求：

1. 先找到 1–3 个最相关章节，再读取完整条目。
2. **必须读完整“备注”**，不要只看标题和“说人话”。
3. 每个数字、法条、论文、政策、统计值必须能回指条目原文。
4. 标记“争议”的条目要把主要限制或反方证据一起呈现。
5. 标记“TODO / 待核实”的内容不能当作确定结论。
6. 若书中没覆盖，明确写“指南未覆盖”，进入增强决策层，不要假装是书里的观点。

## 4. 判断信息是否需要当前核验

读 `references/source-policy.md`。

遇到以下内容时，不要只依赖本地快照：

- 法律、监管、社保、医保、税务、补贴、签证、名单、金额、时限。
- 当前旅行安全、疾病指南、药品/医疗政策。
- 市场费率、价格、产品规则。
- 用户明确要求“现在 / 最新 / 今天”。

如果有联网能力，优先核验官方或一手来源；没有联网能力，就写明本地快照日期和可能过期的部分。

不要用二手媒体覆盖掉更高质量的一手证据。

## 5. 先按指南自己的框架算

指南的原始成本维度：

- 钱：0 / 少 / 多
- 时间：少 / 中 / 多
- 毅力：否 / 些 / 是

收益量级：

- 大 / 中 / 小

证据等级：

- A / B / C

上游性价比算法以 `assets/upstream/index.html` 为准。当前快照的成本权重为：

- 钱 0/少/多 → 0/1/2
- 时间 少/中/多 → 0/1/2
- 毅力 否/些/是 → 0/1/2

成本分为三项相加。收益“大”时，成本分 0 为“极高”，成本分 ≤2 为“高”，其余为“一般”；收益“中”时，成本分 0 为“高”，其余为“一般”；收益“小”为“一般”。

这些只是**作者的性价比判断**，不是科学证据等级。

严格遵守：

- 同一收益口径内可以比较。
- 不同口径之间不要硬排序。
- 证据等级高，不等于收益大。
- 性价比高，不等于适合当前用户。
- “一般”不等于“不该做”。

## 6. 再做增强决策层

指南给出“通常值不值”，增强层回答“对这个用户现在该怎么做”。

涉及复杂人生选择时读 `references/decision-framework.md`，依次判断：

1. **硬约束**：违法、危险、无法承受的亏损、家庭责任等。
2. **尾部风险**：最坏情况是否会毁掉健康、自由、基本现金流或关键关系。
3. **可逆性**：做错以后能不能低成本撤回。
4. **选择权**：哪种方案保留更多未来选项。
5. **信息价值**：能否先花很小成本获得决定性信息。
6. **执行摩擦**：理论收益很好，但用户是否真的能长期做到。
7. **个人偏好**：只有当客观证据不能决定时，再让用户在不可比目标之间做取舍。

不要把这些维度压成伪精确的 87 分、92 分之类总分。需要比较时用“门槛 + 分项表 + 条件结论”。

## 7. 形成行动建议

默认只从四种决策动作中选：

- **做**：证据足、下行可控、与用户约束匹配。
- **不做**：有明确负面证据、尾部风险过大，或收益明显不抵成本。
- **先验证再做**：关键事实会改变结论，且验证成本低。
- **做小规模可逆试验**：方向可能对，但不确定性高，适合先小下注。

若多个方案都合理，不替用户假装存在唯一正确答案。给出条件化结论，例如：

- 如果最看重现金流，A 更匹配。
- 如果最看重未来选择权，B 更匹配。
- 如果目前信息不足，先做 C 的低成本试验。

## 8. 输出格式

根据复杂度选择：

- 简单消费/习惯问题：Quick。
- 一般人生选择：Standard。
- 辞职、买房、婚育、创业、出国、长期职业等高影响问题：Deep。

输出前读 `references/output-contract.md`。

最低输出必须包含：

1. **结论或条件结论**
2. **最关键的 2–5 个理由**
3. **证据来自哪里**
4. **主要代价与最坏风险**
5. **下一步最小行动**
6. **什么情况出现时应改主意**

引用指南时写清：

`《高性价比人生指南》第 X 节第 Y 条（条目标题）`

必要时再附原始来源链接或当前官方核验来源。

## 9. 证据标签

为了让用户知道哪部分来自哪里，复杂回答优先使用：

- `[指南]`：本地《高性价比人生指南》明确支持。
- `[当前核验]`：刚从官方/一手来源核实。
- `[推理]`：基于已知事实做的决策推导，不是指南原文。
- `[偏好]`：取决于用户价值排序，没有客观唯一答案。
- `[未知]`：当前证据不足。

不要把 `[推理]` 写成 `[指南]`，也不要用“研究表明”掩盖没有来源的判断。

## 10. 维护与更新

本 Skill 自带的是固定知识快照，不自动静默更新。

需要更新时，先查看：

```bash
cat assets/upstream/SOURCE.json
```

再运行：

```bash
python3 scripts/update_upstream.py --remote
```

更新后必须重新运行本 Skill 的验证脚本，并检查上游许可证是否变化。
